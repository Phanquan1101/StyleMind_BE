# US-03.05 through US-03.10 Commerce Postman Run Guide

Import `US-03.05-03.10_branch_cart_order.postman_collection.json`.

Set variables:

- `baseUrl`: `http://localhost:8080/commerce` through Gateway, or `http://localhost:8082` direct to Commerce.
- `customerToken`: valid Identity JWT with `CUSTOMER`.
- `adminToken`: valid Identity JWT with `ADMIN`.
- `variantId`: active Commerce variant ID.
- `shippingAddressId`: an address owned by the `customerToken` subject.

Runtime prerequisites:

- In Docker Compose, Commerce receives the internal Identity settings from `docker-compose.yml`:
  `STYLEMIND_JWT_JWK_SET_URI=http://identity-service:8081/.well-known/jwks.json`,
  `STYLEMIND_JWT_JWS_ALGORITHM=RS256`, and
  `STYLEMIND_IDENTITY_BASE_URL=http://identity-service:8081`.
- When running Commerce directly from IntelliJ or `spring-boot:run`, the service defaults to the host-local Identity URLs:
  `STYLEMIND_JWT_JWK_SET_URI=http://localhost:8081/.well-known/jwks.json`,
  `STYLEMIND_JWT_JWS_ALGORITHM=RS256`, and
  `STYLEMIND_IDENTITY_BASE_URL=http://localhost:8081`. Override these only if Identity runs elsewhere.
- Checkout address validation uses the Commerce OpenFeign Identity client and forwards the customer's bearer token to
  `GET /api/v1/me/addresses/{shippingAddressId}`.
- Guest cart requests use `guest_session_key`; user cart, merge, checkout, order and cancellation routes use JWT.

Structural validation:

- The JSON file is Postman collection schema v2.1 and contains Branch, Cart and Orders folders.
- Automated runtime coverage is in `BranchCartOrderPostgresIntegrationTests`; the collection is a manual/API handover artifact and was not executed against a live Gateway in this run.
