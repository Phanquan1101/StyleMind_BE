# US-03.02-03.04 Postman Run Guide

1. Import `US-03.02-03.04_products_variants_images.postman_collection.json`.
2. Set `baseUrl` to the Commerce entrypoint, for example `http://localhost:8082`.
3. Product list/detail and public variant batch lookup require no JWT. Set `bearerToken` only for Admin requests; those require a JWT whose `roles` claim contains `ADMIN`.
4. Create or reuse Category and Brand rows first, then set `categoryId` and `brandId`.
5. Create a Product, copy `product_id` into `productId`, then create a Variant and copy `variant_id` into `variantId`.
6. Set `CLOUDINARY_URL` in the Commerce process environment using the value from the Cloudinary console. Optionally set `CLOUDINARY_FOLDER` (default: `stylemind/products`). Never put the real credential in this collection or commit it.
7. `POST /api/v1/admin/variants/{variantId}/images` uploads the file to Cloudinary and persists the returned HTTPS `secure_url`. The response `Location` and `image_url` therefore point directly to Cloudinary. The legacy `/api/v1/variant-images/{imageId}/content` route remains only for images that were stored locally before this change.
8. Product and Variant DELETE operations are idempotent soft-deletes that set their existing status to `INACTIVE`; IDs and unique SKU values remain reserved. Variant Image DELETE remains permanent and removes both database metadata and the Cloudinary asset.
9. Every variant response now includes `available_quantity`. A newly created admin variant starts at `0`; the tracked development seed starts each seeded variant at `20`.

To load the shared development catalog, set `STYLEMIND_CATALOG_SEED_ENABLED=true` before starting Commerce. The runner idempotently groups 600 source images into 381 product families and 2,120 color/size variants from `src/main/resources/db/seed/development-catalog.json`. Re-running it updates catalog metadata but never resets existing stock.

Structural validation: collection JSON was created as static handover content. Automated HTTP tests cover the same API shapes with MockMvc and disposable PostgreSQL.
