# US-03.01 Postman Run Guide

1. Import `US-03.01_categories_brands.postman_collection.json`.
2. Set `baseUrl` to the Commerce entrypoint: `http://localhost:8082` direct or `http://localhost:8080/commerce` through Gateway.
3. Category and Brand public reads require no JWT. Set `bearerToken` only for Admin requests; those require a JWT whose `roles` claim contains `ADMIN`.
4. Run create requests first, then copy the returned `id` into `categoryId` or `brandId` before get/replace/delete.
5. Negative requests are included for duplicate category slug (`409 DUPLICATE_SLUG`) and invalid brand slug (`400 INVALID_REQUEST`).
6. Category and Brand DELETE operations are idempotent soft-deletes: they set `is_active=false`, keep the row and reserve its slug. Public reads hide inactive records; the Admin list/detail requests include them and can be used before reactivation through PUT.

Structural validation: this collection is static JSON and complements the automated MockMvc/PostgreSQL tests. It was not executed against a manually started HTTP service in this turn.
