# DEC-030 — Atomic Guest-to-User Cart Merge

Status: APPROVED

Decision Authority: Phan Đoàn Thế Quân — Solo Owner of StyleMind

Date: 2026-09-21

Source Decision Review: DR-005

Resolved OPEN Questions: OPEN-010

Partially addressed OPEN Questions: OPEN-009

## Approved decision

After login, the Guest Cart is merged into the authenticated User Cart.

1. Duplicate Product/Variant quantities are combined.
2. If the combined quantity exceeds currently available stock, the entire merge fails. No Guest Cart item is partially merged and the User Cart remains unchanged by that attempt.
3. If any Variant is inactive, unavailable, invalid or no longer purchasable, the entire merge fails and the conflicting item is identified clearly.
4. A price change does not invalidate the merge. The latest authoritative Catalog/backend price is used and the user is informed when it differs from the price previously displayed in the Guest Cart.
5. The Guest Cart is cleared or retired only after a complete successful merge.
6. When merge fails, the Guest Cart remains available so the user can correct or remove conflicts and retry.
7. Partial merge and per-item interactive conflict resolution are out of scope for V1.

Cart price is not price-locked. Architecture and transaction implementation remain deferred.

## Scope implications

This resolves the V1 product outcome for duplicate quantities, merge conflicts, price changes, retry and Guest Cart clearing. It does not select a session mechanism, quantity bounds or cart mutation contract.
