# DEC-031 — Atomic Product-Level Checkout

Status: APPROVED

Decision Authority: Phan Đoàn Thế Quân — Solo Owner of StyleMind

Date: 2026-09-21

Source Decision Review: DR-006

Partially addressed OPEN Questions: OPEN-011, OPEN-014

## Approved decision

Checkout is all-or-nothing at the product level.

Before Order creation, the backend must revalidate Product/Variant validity, active status, requested quantity, current stock and current authoritative price.

1. If any item fails validation, the Order is not created and checkout does not continue partially.
2. No invalid item is silently removed. The affected item and reason are shown to the user.
3. If price changes before final Order creation, the new authoritative price and updated checkout amount must be shown and reconfirmed. The system must not silently charge a changed total.
4. Partial checkout is out of scope for V1.
5. V1 makes no separate user-visible promise that stock is reserved for a fixed period during ordinary checkout.
6. Successful Order creation must not be allowed for stock that cannot actually be committed; the technical mechanism remains a later SAD/implementation concern.
7. If Order creation fails, no successful Order is presented. The user receives a recoverable error and may retry after revalidation.
8. After successful Order creation, payment behavior follows DEC-033.

## Scope implications

This establishes the customer-visible checkout guarantee and retry outcome. It does not decide stock ownership, reservation/deduction mechanism, transaction boundaries, compensation or detailed recovery contracts.
