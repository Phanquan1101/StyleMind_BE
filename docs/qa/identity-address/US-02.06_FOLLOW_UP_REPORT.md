## HTTP security investigation

The original matcher covered GET but not HEAD. A temporary test-only reproduction against the original matcher used the embedded server and an unsupported STYLIST role. All four HEAD paths returned HTTP 200 and reached the instrumented business service (four handler calls). The reproduction output is retained in ignored local evidence at target/us0206-followup-20261009T1200/head-baseline-repro-with-handler.log.

After the fix, headUsesTheSameRoleAndAuthenticationGateAsGet verifies all four routes:

- Missing, malformed, signature-tampered, and expired JWTs return 401.
- A valid JWT with an unsupported role returns 403 and never calls an Address/location handler.
- CUSTOMER and ADMIN tokens are accepted. A different CUSTOMER cannot HEAD another owner’s Address; it receives the same 404 as GET.
- The owner’s full Address state and default invariant are unchanged by HEAD.

unsupportedMethodAndOptionsKeepFrameworkAndCorsBehavior confirms PATCH to the province lookup remains 405 for an authenticated request and 401 without a token. OPTIONS preflight remains denied (403 with a token, 401 without one), emits no Access-Control-Allow-Origin, and calls no business handler. No CORS policy was introduced. The tests do not treat a 404 for an unmapped URL as evidence of protection.

## PostgreSQL race coverage

All five concurrent scenarios now use a shared contention harness. Requests start together; the first pauses after the service has acquired the owning account row lock. The test observes the second PostgreSQL backend waiting on that row lock in pg_stat_activity before releasing the first. The latch is released in finally with bounded timeouts. This proves actual transaction overlap and database contention rather than relying on request start timing alone.

For every pair the tests assert both HTTP outcomes and final rows/default invariants:

1. Concurrent first Address creates.
2. Concurrent switches of the default Address.
3. Deleting the current default concurrently with setting its alternative as default.
4. PATCH concurrently with DELETE, including the absence of a resurrected row.
5. Deleting the last Address concurrently with creating another.

The assertions allow either valid serial order where both are permitted, and check row IDs, counts, default count, response bodies/statuses, and unchanged surviving Address state.

## Postman negative-state checks

The collection now has 39 requests. It captures canonical full Address state immediately before each negative-request group and compares it afterward. The comparison sorts by address_id, checks all seven response fields (address_id, label, recipient_name, recipient_phone, address_line, ward_code, is_default), and separately checks property presence so JSON null is not conflated with a missing field.

Snapshots cover the foreign-owner attempts, invalid-input and attempted-owner-override group for both A and B, and the rejected deletion of a default Address with alternatives. Every authenticated request explicitly binds Authorization to the matching run-scoped A or B token. The intentionally missing/malformed-auth cases remain unauthenticated. No example credentials or tokens are embedded in the collection.
