## Requirement mapping and result

| Story requirement | Implementation, authorization and transaction |
| --- | --- |
| Authorized API; record money only after collection | Existing Admin JWT POST /api/v1/admin/cod-collections is preserved. Strict UUID/whole-VND/exact amount/method/time validation, attempt row lock, one immutable ledger with Admin identity, SETTLED and outbox in one Payment transaction. Pending creation writes no cash record. Invalid/failed/repeated/concurrent collections cannot credit twice. |
| Send confirmed COD to Commerce without Notification | Shared sender selects only SETTLED COD/SePay attempts joined to a financial transaction; method is sourced from the settled attempt, and conflicting stored payload method is rejected. Existing service credential, stable event ID, retry, ACK validation and rotating batch behavior are preserved. HTTP is outside the local write transaction. |
| Durable Commerce handling | Strict authenticated PaymentConfirmed parsing accepts COD. Owner/method/exact amount and Order state are checked under a row lock; event receipt/fingerprint and APPLIED uniqueness prevent repeated effects. COD PLACED/PROCESSING/SHIPPED/COMPLETED persists COD_COLLECTION_CONFIRMED without any fulfilment/history change. Missing/foreign/mismatched/CANCELLED/PENDING_PAYMENT Orders reconcile. Already-applied receipts remain idempotent even if fulfilment later advances. |
| Failure/retry and tests | Ledger/outbox failure rolls back collection; inbox failure is not acknowledged; receiver outage/lost ACK retries the same event. Rejection publishes one durable Admin exception while keeping real settlement. Tests include pending, failure, repeated/concurrent calls, distinct event IDs, content conflicts, method/owner isolation, invalid authorization, SePay regression and V7 -> V8 upgrade preservation. |

No Notification HTTP call or SMTP delivery participates in collection/delivery. No shared database access, new Order payment-status column/API, new Payment migration, refund workflow or SHIPPED-only collection guard is added. Existing Commerce JPA code is inherited; all new persistence remains JDBC.
